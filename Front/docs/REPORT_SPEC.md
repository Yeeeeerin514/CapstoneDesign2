## 앱 개요 및 역할 정의

당신은 임금체불 피해 근로자를 위한 신고 보조 앱의 AI 어시스턴트입니다.

이 앱은 다음 세 가지 핵심 기능을 제공합니다:
1. **신고 가이드** — 임금체불 진정서 작성부터 사건 종결까지 단계별 안내
2. **공동대응 매칭** — 같은 업장 피해자를 연결해 집단 진정 지원
3. **멘토 매칭** — 같은 경험을 해결한 동료 근로자(멘토)와 1:1 연결

**당신은 공인노무사 또는 변호사가 아닙니다.** 법률 자문이 아닌, 절차 안내와 경험 공유를 제공합니다.
복잡한 법적 판단(근로자성 다툼, 형사 고소, 민사 소송)이 필요한 경우에는 반드시 공인노무사 또는 변호사 상담을 권유하세요.

## 실제 임금체불 신고 절차 (사실 기반)

사용자 안내 시 아래 실제 절차를 기준으로 설명합니다.

### 전체 흐름

```
1. 진정 제기
   - 고용노동부 노동포털(labor.moel.go.kr) 온라인 신청
   - 또는 사업장 소재지 관할 고용노동관서 직접 방문
   - 진정서 기재사항: 근로자 인적사항 / 사업주 정보 및 주소 /
     체불 기간 및 금액 / 입증자료(근로계약서, 급여명세서, 통장 내역, 출퇴근 기록)

2. 근로감독관 배정 및 출석조사
   - 배정 후 1~2주 이내 출석요구서 발송
   - 처리기간 원칙 25일(토·공휴일 제외), 2차까지 연장 가능
   - 진정인이 2회 이상 불출석 시 사건 종결(재진정 가능)

3. 시정지시
   - 법 위반 사실 확인 시 사업주에게 시정지시
   - 시정 완료 → 사건 종결

4. 미이행 시 형사입건
   - 시정 미이행 → 형사입건 → 검찰 송치
   - 임금체불 사업주: 3년 이하 징역 또는 3,000만원 이하 벌금

5. 이후 단계 (임금을 끝내 받지 못한 경우)
   - 체불 임금등·사업주 확인서 발급 (고용노동관서)
   - 대한법률구조공단 민사소송 (평균임금 400만원 미만 무료)
   - 대지급금 제도 활용 (사업주 도산 등)
```

### "해결됨"의 정의 (앱 내 통일 기준)

| 상태 | 정의 | 앱에서의 표시 |
|------|------|--------------|
| 진행 중 | 진정 접수 ~ 시정지시 이전 | 🔵 진행 중 |
| 시정지시 | 노동청이 사업주에게 지급 명령 | 🟡 시정지시 완료 |
| **해결됨** | 노동청 사건 종결 통보 + 사용자 자가 확인 | ✅ 해결됨 |
| 미수령 | 시정 미이행 → 다음 단계 필요 | 🔴 미수령 (민사 안내) |

> **중요**: 체불 임금등·사업주 확인서는 "해결됨"이 아닙니다. 이는 임금을 받지 못한 사람이 민사소송/대지급금을 청구하기 위해 발급받는 서류입니다. 멘토 자격 기준에서 이를 "해결 증빙"으로 잘못 사용하지 마세요.

## 핵심 기능 1: 신고 프로세스 (앱 화면 흐름)

### 화면 ① — 신고 시작

사용자가 신고를 시작하면 가장 먼저 수행할 작업:

```
[입력 받기]
- workplaceName (업장명)
- 체불 기간
- 체불 금액 (개략적으로도 OK)
- businessRegistrationNumber (선택, null 허용 — 나중에 연동)

[즉시 수행]
- 같은 workplaceName으로 신고한 다른 사용자 탐색 (mock 데이터)
- 있으면 → 공동대응 제안 (화면 ②로 분기)
- 없으면 → 개별 진정 흐름 (화면 ③으로 직행)
```

안내 메시지 예시:
> "OO카페에서 신고를 시작했군요. 같은 업장에서 신고한 분이 2명 있어요. 함께 대응하면 근로감독관 배정 시 더 강한 압박이 됩니다. 공동대응에 참여하시겠어요?"

### 화면 ② — 공동대응 그룹 (진정서 작성 이전 단계)

> **핵심**: 공동대응은 진정서 작성 이전에 결성해야 합니다.
> 이유: 공동대응의 실질적 가치는 (a) 증거자료 공유, (b) 대표자가 통합 자료 첨부, (c) 동시 진정으로 사업주 압박에 있기 때문입니다.

```
[그룹 생성 조건]
- 같은 workplaceName 피해자 2명 이상 참여 시 그룹 생성
- 향후: 사업자번호(businessRegistrationNumber) 기반으로 고도화

[대표자 선출 — 방식 (B)]
1. 그룹 생성 후 48시간 동안 자원자 모집
2. 자원자 1명 → 자동 확정
3. 자원자 여러 명 → 피해액 기준 미니 투표 (그들끼리)
4. 자원자 0명 → 피해액 최대자 자동 선출 (수락/거절 가능, 거절 시 다음 순위)

[대표자 권한]
- 통합 진정서 작성자 (대표 제출자)
- 멘토 매칭 우선 배정
- 해결 후 후기 작성 시 "공동대응 대표자" 배지 → 멘토 가중치 +30점

[그룹 기능]
- 그룹 채팅 (증거자료 공유, 일정 조율)
- 출석조사 일정 공유
```

### 화면 ③ — 진정서 작성 (멘토 매칭 주 진입점)

```
[공동대응 모드]
- 대표자: 통합 진정서 + 개별 진정서 동시 작성
- 나머지 멤버: 개별 진정서만 작성, 그룹 공유 증거자료 자동 연동

[개별 모드]
- 본인 진정서만 작성

[멘토 매칭 권유 — 주 진입점]
진정서 초안 작성 화면 상단에 배너 표시:
"진정서 작성이 막막하다면? 같은 경험을 가진 멘토와 매칭하세요 (10,000원)"
→ [멘토 찾기] 버튼 → 멘토 목록 화면

진정서 항목 안내:
1. 근로자 인적사항
2. 사업주 정보 및 사업장 주소
3. 체불 기간 및 금액
4. 입증자료 (근로계약서, 급여명세서, 통장 내역, 출퇴근 기록)
5. 진정 취지 및 이유 (법률 용어 불필요, 사실을 정확히)
```

### 화면 ④ — 사건 진행 (보조 멘토 진입점)

```
[진행 상태 타임라인 표시]
✓ 진정 접수 → ✓ 근로감독관 배정 → → 출석조사 → 시정지시 → 해결

[보조 멘토 진입점 조건별 표시]
- 출석조사 통보 수신 시: "출석조사가 처음이라 떨리시나요? 멘토와 준비하세요"
- 신고 후 7일째 아무 진행 없을 시: 자동 재권유

[공동대응 그룹 바로가기]
- 그룹 채팅, 출석조사 일정 조율
```

### 화면 ⑤ — 해결 확인

```
[트리거]
- 노동청 사건 종결 통보 수신 시 자동 표시
- 또는 사용자가 수동으로 "해결됐어요" 선택

[이중 확인]
"임금을 실제로 받으셨나요?"
→ 네, 받았어요 → 상태: ✅ 해결됨 → 후기 작성 안내 (화면 ⑥)
→ 아직 못 받았어요 → 다음 단계 안내:
   - 시정지시 미이행 확인
   - 체불 임금등·사업주 확인서 발급 안내
   - 대한법률구조공단 민사소송 연계
   - 대지급금 제도 안내
```

## 핵심 기능 2: 멘토 매칭

### 멘토 자격 기준

**필수 조건 (둘 다 충족해야 함)**:
1. 앱 내에서 임금체불 신고 프로세스를 진행한 이력
2. 사건 종결 + 본인 자가 확인 ("받았어요" 체크)

**가중치 점수 (매칭 우선순위)**:
- 공동대응 대표자 이력: +30점
- 증빙서류 업로드(시정지시서 또는 입금 내역): +20점
- 후기 별점 평균 × 10점
- 해결까지 걸린 기간 (짧을수록 점수 높음)
- 업장 업종 매칭 (카페 피해자 → 카페 경험 멘토)

**인증 배지**:
- 증빙서류 업로드 시: "🛡 인증된 멘토" 배지
- 공동대응 대표자 이력 시: "🏆 공동대응 대표" 배지

**멘토 포지셔닝 주의사항**:
멘토는 공인노무사·변호사가 아닌 "동료 피어(peer)"입니다.
모든 멘토 연결 화면에 면책 문구 표시:
> "이 멘토는 법률 전문가가 아닌 같은 경험을 가진 동료 근로자입니다. 법률 자문이 필요하시면 공인노무사 또는 변호사 상담을 받으세요."

### 결제 (PoC: Mock)

```typescript
// payment/types.ts

  name: 'mock' | 'kakaopay' | 'toss' | 'card';
  charge(userId: string, amount: number, metadata: object): Promise<PaymentResult>;
```

**분배 구조**:
- 멘티 결제: 10,000원
- 멘토 수령: 5,000원
- 플랫폼 수수료: 2,000원
- 멘티 환급 (해결 후): 3,000원

**환급 조건**: "해결됨" 상태 확인 시 (노동청 종결 통보 + 자가 확인)

**감사 후원**: 해결 후 멘티가 추가 후원 가능 (선택)

## 핵심 기능 3: 후기 시스템

### 신고 탭 화면 구조

```
[신고 탭]
├── 섹션 1: 진행 중인 내 사건
│   ├── 사건 카드 (업장명, 현재 상태, 상세보기)
│   └── [+ 새 사건 신고하기] CTA
│
├── 섹션 2: 해결 후기 둘러보기
│   ├── 필터: [전체] [같은 업종] [같은 지역]
│   ├── 후기 카드 (별점, 업종, 해결 기간, 닉네임, 배지)
│   ├── [멘토에게 연결 (10,000원)] 버튼
│   └── [후기 더 보기 →]
│
└── 섹션 3: 내 후기 쓰기 (해결된 사건이 있을 때만 활성화)
    └── [후기 쓰기 →] → 후기 작성 폼
```

### 후기 작성 항목

```
1. 닉네임 (실명 X)
2. 업장명 마스킹
   - 공개 후기: 자동 마스킹 (예: "OO카페 강남점" → "강남점")
   - 공동대응 매칭 (내부): 풀네임 유지
   - 정부 공개 체불사업주 명단에 있는 경우: 풀네임 표시 가능
3. 사건 메타정보 (공개)
   - 업종 / 체불 기간 / 해결까지 걸린 시간
4. 별점 (해결 만족도, 5점 만점)
5. 노하우 구조화 입력
   - 진정서 작성팁
   - 출석조사 팁
   - 사업주 협상 팁
6. 자유 서술
7. [선택] 멘토로 등록하고 상담 요청 받기
   → 체크 시 멘토 프로필 셋업 (자격 기준 자동 확인)
```

### 후기 → 멘토 매칭 동선

```
[후기 카드 탭]
→ [후기 상세]
   ├── 사건 요약 (마스킹된 업장명, 체불기간, 금액 범위)
   ├── 해결 타임라인 시각화
   ├── "내가 한 일" (단계별 노하우)
   ├── "이렇게 했으면 더 좋았을 것"
   ├── 첨부 (마스킹 진정서 샘플 — 작성자 동의 시)
   └── [이 분과 1:1 멘토 매칭하기 (10,000원)]
       → 결제 (mock) → 매칭 알림 → 채팅방 개설
```

## 현재 코드와의 주요 차이 (구현 시 참고)

1. **사건 상태 모델 충돌**: 스펙 5-val(`pending`/`inspecting`/`correction_ordered`/`resolved`/`unresolved`) ↔ 현재 `entities/report/model/types.ts`의 6-val(`evidence-collecting`/`draft-ready`/`submitted`/`under-review`/`resolved`/`closed`). 마이그레이션 또는 매핑 필요.
2. **공동대응**: `ReportSolidarity { isJoined, participantCount }`만 존재. `Group`/`GroupMember`/대표자 선출 시스템 통째로 신규 슬라이스 필요.
3. **멘토 매칭**: `entities/mentor`와 `features/mentor-match`가 스켈레톤. 가중치 점수/자격 검증 로직 통째로 신규.
4. **결제**: 미존재. `payment/` 슬라이스 신규 + `PaymentProvider` 인터페이스 + mock 구현체 필요.
5. **후기 시스템**: 미존재. Review 모델 + 마스킹 + 후기 작성 폼 신규.
6. **탭 구조**: 현재 5탭(홈/관심업장/근무기록/신고/MY) ↔ 스펙 4탭(홈/신고/공동대응/MY). "관심업장"/"근무기록"이 사라지는지 유지하는지 확인 필요.
7. **"해결됨" 엄격 정의**: 멘토 자격 검증 시 체불확인서를 해결 증빙으로 잘못 사용하지 않도록 store/validator에 반영.
8. **법적 면책 문구**: 멘토 화면 진입 시 + 복잡한 사건 감지 시 자동 모달.
